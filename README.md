# NearDrop 安心傳檔

Windows 10／11 x64 桌面軟體，以 C#、WPF、.NET 10 LTS 及**未修改的官方 Syncthing 2.1.7**傳輸。這是可建置及實際傳檔的 0.1 預覽版；跨網路實機驗收尚待執行，請先使用可重建的測試資料。

## 安裝與使用

Windows x64 安裝檔可從 [GitHub Releases](https://github.com/Yanjin-0/NearDrop/releases) 取得。從這份原始碼建置會在 `artifacts/` 產生 `NearDrop-0.1.15-win-x64-Setup.exe`。單檔安裝包內含 .NET 10.0.15 與 Syncthing，無須另外安裝元件、註冊帳號或取得管理員權限。安裝到 `%LOCALAPPDATA%\Programs\NearDrop`。目前安裝檔尚未簽署，請從可信來源取得並比對發佈的 SHA-256。

1. 兩人打開「我的裝置」，透過可信的通訊管道交換、核對**雙方完整裝置 ID**，各自加入對方並勾選已核對身分。朋友清單只存在本機。已連線只代表傳輸連線，不是另一個人身分的保證。
2. 將檔案或資料夾拖到「傳送」，選朋友，按「傳送」。支援檔案／資料夾選取按鈕；多個同名頂層項目須分批送。
3. 朋友到「接收」選取邀請並接受。畫面會保留該筆選取，完成後可直接按「保存到收件資料夾」。已完整接收的工作停止共享後仍可獨立保存。保存時會短暫停止所有傳輸，完整性驗證通過後才搬到不共享的位置。
4. 「自動傳送」可為每個專用資料夾指定一位朋友。對方明確接受後，使用 Syncthing 原生檔案監控，等待 10 秒後處理變更；每小時補掃一次。支援暫停／恢復及離線續傳。可建立多個資料夾，**重疊資料夾不允許**。在「自動傳送」選取工作並按「開啟同步資料夾」，即可查看本機內容。接收端也可在「接收」選取該筆工作並開啟。
5. 設定中可加入檔案總管右鍵「傳送到 → NearDrop」（Windows 11 通常需「顯示其他選項」）、啟用 Ctrl+Alt+N 快捷鍵，或設定登入 Windows 時背景啟動。快捷鍵偏好會保留，且只從前景檔案總管讀取選取項目。部分分頁與虛擬資料夾請改用拖曳。

接收頁籤和系統匣選單會顯示待處理數量。收到新邀請或檔案接收完成時，Windows 通知會提供接收頁入口；單一通知會嘗試定位對應工作，多筆則直接前往待處理項目。通知只顯示筆數。可在設定關閉通知，接收頁的數量仍會顯示。

不想接收時可選取邀請並按「拒絕邀請」。程式會在本機記住這次決定。日後要收件，請發送者建立新邀請。收件暫存磁碟設定保留至少 2 GB 空間，跨磁碟保存前也會檢查目的磁碟是否能容納檔案和保留空間。

「傳送」清單支援追加檔案與資料夾、移除單項及清空，重複選取的路徑會合併。建立暫存時會顯示目前檔案進度及累計資料量。可在建立邀請前取消，選取清單會保留。資料夾容量在準備時才累計。

「傳輸紀錄」支援搜尋工作名稱、朋友與日期，狀態與傳送／接收方向可一起篩選。每列會顯示方向和建立時間。從「傳送」送出後會選取新工作，必要時清除原篩選。選取收件可直接前往該筆接收或保存。按「清除條件」可以回到全部紀錄。

要回收單次傳送的暫存空間，先請朋友確認收件已獨立保存，再到「傳輸紀錄」選取該工作。可用「開啟傳送暫存」檢查內容。按「取消共享」後，按「清理傳送暫存」並確認。清理會短暫暫停引擎，只移除這筆工作在本機的暫存副本，保留來源、收件與紀錄。若檔案被其他程式鎖定，關閉該程式後可重試清理。清理開始後要再傳送，請重新選取來源建立新工作。

單次傳送**先複製一份**至發送端暫存並計算雜湊，需要約一份額外空間；檔案寫入鎖定時會失敗，請關閉正在寫入的程式後重新選取傳送。相同磁碟收件保存使用重新命名搬移；不同磁碟需要再複製一份並重驗。發送端不自動清除暫存，因為目前沒有跨裝置「正式保存」回執；「對方已同步」**不等於**「已獨立保存」。取消共享也不刪除本機檔案。準備中斷或來源仍在寫入的工作，需要重新選取來源建立新的工作。

持續資料夾是**同步**，修改與刪除會傳播。Send Only 只阻止反向更改來源。接收端保留最近 5 個遠端更動版本，備份仍需另外建立。對於長時間開啟寫入的檔案，請先在同磁碟的非共享位置完成寫入，再搬到監控資料夾。10 秒等待可以合併短時間變更，無法判斷其他程式是否稍後還會寫入。持續收件位於應用程式的獨立 Incoming 區。如需永久副本，先停止該共享，再自行複製至不共享的位置。

## 建置

需要 Windows x64、.NET SDK 10.0.301（或相容修補版）、PowerShell 7，以及首次還原時的 HTTPS 網路。不需要 Go、Node 或第三方安裝器。**朋友不需要 SDK**。

```powershell
pwsh -File scripts/build.ps1
```

腳本下載固定版官方 Syncthing 並驗證兩層 SHA-256；還原 Microsoft 官方 runtime 套件，編譯、執行實際雙節點整合測試，再發佈自含式 WPF 程式及單一安裝 EXE。每項失敗會停止。測試使用隔離目錄與本機 TCP，關閉公共探索、中繼及 NAT，不會讀取私人文件。`-SkipTests` 只供已驗證的重複封裝；發佈前不要省略測試。

Git 只保留原始碼、文件、腳本和 `vendor/syncthing.lock.json`。引擎由建置腳本下載並驗證簽章。安裝檔與校驗資料放在 Releases，使用者設定、測試資料和建置輸出均由 `.gitignore` 排除。

```powershell
pwsh -File scripts/test.ps1
```

`artifacts/app/NearDrop.exe` 可直接執行。一般開發建置：`dotnet build NearDrop.sln -c Release -m:1 -p:UseSharedCompilation=false`（本機 SDK 的 Android 工作負載權限異常時，設 `MSBuildEnableWorkloadResolver=false`）。
