# 技術架構

## 分層

`Relay.App` 是繁體中文 WPF 介面，僅負責選檔、選朋友、狀態呈現、通知與使用者確認。視窗支援縮放、每螢幕 DPI、滾動與虛擬化清單。`MainWindow` 的事件呼叫應用服務；不直接拼裝引擎共享設定。

`Relay.Core` 包含 `ITransferEngine` 邊界、`PairingService`、`TransferService`、持久化狀態、路徑驗證及不可變暫存。服務以 semaphore 序列化工作，狀態以 flush + 原子替換保存並保留 `.bak`。損壞紀錄不會靜默重置。未將 REST JSON 全面抽象成通用傳輸模型；未來替換引擎仍須重寫設定與進度轉接器。

`Relay.Windows` 負責使用者限定 ACL、程序生命週期、Windows Job Object、REST HttpClient、單實例命名管線、開機登入與檔案總管整合。命名管線僅當前使用者可連線，限制 1 MiB、4,096 路徑與 3 秒讀取時間。外部參數只填入選取清單，不自動傳送或執行檔案。

`Relay.Setup` 為自含式 WPF 安裝器。內嵌完整程式 ZIP、驗證負載及官方引擎雜湊，安裝至目前使用者目錄，建立開始功能表與 HKCU 卸載項目。沒有遠端下載執行或自動更新。卸載從暫存副本執行，僅刪除明列的檔案及空資料夾，保留未知檔案與所有個人資料。暫存的卸載 EXE 由 Windows 暫存清理處理。

## 引擎啟動

1. 鎖定使用者 profile，禁止相同設定的多實例；設定目錄拒絕重新解析點，ACL 限當前使用者與 SYSTEM。
2. 驗證固定的 Syncthing EXE SHA-256。
3. 僅首次呼叫 `generate`；設定遺失或金鑰遺失時停止，避免無聲改變身分。
4. 首次移除預設 Sync 共享。每次啟動重設本機 GUI/API、禁止自動升級、遙測、當機回報、自動接受與介紹人。
5. GUI 僅 `127.0.0.1`，隨機可用連接埠、每次隨機 API key；GUI 帳密由隨機密碼保護。API 不經代理、不跟隨重新導向；啟動時驗證就緒。隨機連接埠有極小競爭窗口，衝突會報錯，不會轉向外網。
6. Syncthing 在 Job Object 中執行，正常退出透過 REST shutdown，逾時則終止該程序樹；當機由 Job Object 收尾。保存時保留 profile 鎖並短暫停止、重啟引擎。

持續傳輸來源只設 Send Only；接收只設 Receive Only。每份共享只有本機與一位明確朋友的完整裝置 ID。接受邀請限制為已加入的朋友、唯一來源、已知 `nd-once-<GUID>` / `nd-live-<GUID>` 格式，從不使用對方提供的路徑或檔名建立本機收件根目錄。

## 單次保存狀態機

`準備中 → 完整暫存+清單 → 已排入 → 對方已同步（保存未知）`。

來源以禁止寫入／刪除的讀取鎖逐檔複製，使用固定 128 KiB 緩衝並計算 SHA-256。先完成暫存及清單，才共享；來源原檔不參與 Syncthing。清單在 `neardrop-manifest.json`，有效負載在 `Files`，保留頂層名稱、階層與空目錄。上限 100,000 項、24 MiB 清單。不是跨檔案交易快照：來源目錄在建立副本時新增的項目不保證納入，資料庫／持續寫入資料應先停止或匯出。

收件：`手動接受 → 接收中 → 已接收待保存 → 寫入保存目的日誌 → 撤共享 → 停引擎 → 驗證清單及所有內容 → Zone.Identifier → 原子搬移 → 已獨立保存`。完成後不再是 Syncthing 資料夾。跨磁碟採 `.saving`、重驗後重新命名，失敗不清除來源。意外中斷後可從保存日誌與唯一目的目錄重試；跨磁碟殘留 `.saving` 需人工檢查，不會覆寫或自動刪除。

沒有自行設計的網路加密、P2P、穿透或同步協定。清單只是檔案層的收件完整性與保存管理，不是新的傳輸協定。尚無跨裝置保存回執，因此發送端暫存永不自動清理。

## 進度與資源

每 3 秒取得狀態；不掃描整顆磁碟。Syncthing 使用原生檔案監控，延遲 10 秒並每小時補掃。工作顯示總容量、完成容量、百分比、近期完成容量／秒與直連／中繼類型；近期完成速率根據區塊進度，並非網卡瞬時吞吐。傳輸百分比不當成正式保存證明。仍使用 API 輪詢，數千個活躍工作時需改事件驅動及限制活躍數。

第一階段引擎與配對、第二階段傳送及持續資料夾、第三階段保存及隔離均有真實雙節點自動測試；第四階段有安裝器、系統匣與 Shell 整合，實機驗收範圍見 TESTING。
