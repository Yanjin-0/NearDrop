# 測試與驗收

## 已執行

0.1.6 增加不顯示視窗的 WPF 測試，透過真實的搜尋框、下拉選單、清單與按鈕驗證各種傳輸紀錄查詢。測試會確認未建立原生視窗控制代碼。執行 `scripts/build.ps1` 時預設包含此測試和本機實傳。封裝後可用 `pwsh -File scripts/test-package-background.ps1` 進行靜默隔離安裝與卸載。這些測試不操作主機桌面。需要檢查實際畫面、視窗操作或 DPI 時，另安排 Windows Sandbox 內的 winapp 測試。

0.1.5 的安裝介面回歸涵蓋待處理數量、定位待保存工作、只記錄可處理項目的通知，以及關閉通知後保留數量提示和設定。`pwsh -File scripts/test-incoming-ui.ps1` 可用已發佈的程式和 winapp 重跑本機雙實例實傳。測試確認邀請和待保存各記錄一次通知、保存後數量歸零，且收件 SHA-256 與原檔一致。Windows 通知是否彈出受系統設定影響，沒有使用通知中心本身的呈現作為通過條件。

0.1.4 新增選取清單追加、去重、移除及清空的 winapp 檢查。核心測試在建立暫存期間取消，檢查沒有 Syncthing 共享、來源仍存在且部分暫存已清理。

0.1.3 回歸重點為配對欄位的 UIA 名稱、必要欄位未填時停用加入、傳送空白狀態停用送出、直接導向配對、按工作狀態顯示收件動作、傳輸紀錄停用不適用的操作，以及頁面切換時提示不外溢。

0.1.2 的暫存清理測試涵蓋仍在共享時拒絕刪除、本機紀錄與引擎狀態不一致時拒絕刪除、鎖定檔案造成的清理中斷和重試、阻擋非暫存路徑，以及保留來源、其他傳送工作、收件端正式檔案及工作紀錄。

0.1.1 回歸範圍新增拒絕邀請後的持久化及舊邀請重放、收件磁碟門檻與既有共享遷移，以及使用 winapp 在隔離安裝中檢查快捷鍵偏好重啟後恢復。磁碟門檻使用邊界值與真實引擎設定驗證，沒有刻意填滿實體磁碟。

2026-11-18 在同一台 Windows 電腦執行真實官方 Syncthing，使用獨立身分、目錄、資料庫和本機連接埠。一般測試使用 64 MiB 與 250 個小檔。壓力測試使用 1 GiB 隨機資料與 2,000 個小檔，另用第三節點驗證不同朋友的隔離。

- 驗證裝置 ID 持久化、重複實例阻擋、回環 API、匿名存取拒絕、雙向授權、未知節點不自動加入、手動接受資料夾及解除配對撤銷權限。
- 實際傳輸保留繁體檔名、目錄結構及空目錄。收件後撤共享並逐檔驗證，收到的檔案帶網際網路來源標記。刪掉發送端原始檔與暫存檔、重新掃描再撤銷共享後，正式收件仍完整。修改驗證樣本後，系統拒絕保存。
- 原生監控偵測實際檔案修改。測過固定資料夾暫停／恢復、離線重啟續傳、單向資料夾設定。第三節點即使已配對且知道另一位朋友的共享 ID，也無法取得該資料夾的檔案。
- 在同機回環，以同一個 1 GiB 檔案及 2,000 個小檔測得單次傳送約 24.6 秒，包含建立暫存、接受及傳輸，計時在獨立保存前結束。固定資料夾初始同步約 15.7 秒，從開始設定監控到接收完成，使用預先準備好的同批檔案與另加一個 5 位元組監控測試檔。單一檔案修改約 11 秒送達，其中含 10 秒監控延遲。量測只反映這台電腦和這批測試資料。
- 使用 winapp 檢查 WPF 在 150% DPI 的設定與傳送頁、無收件朋友提示、實際選取測試檔案及正常退出。重新驗證傳送按鈕在預設視窗內可見。以非管理員權杖執行隔離安裝，確認從安裝目錄載入內附的 `coreclr.dll` 與 `hostfxr.dll` 並產生裝置 ID。從該安裝的卸載程式移除後，測試收件、裝置憑證及額外加入的備份檔均保留。
- 在 Windows 11 Pro（組建 26300）跑通 41 項本機整合檢查，其中 4,097 MiB 隨機檔與 2,000 個小檔分別以單次與固定資料夾傳送。單次從建立暫存到接收完成約 62.8 秒，固定資料夾從啟用到同步完成並核對大檔約 28.2 秒。兩份接收端大檔的 SHA-256 均與原始檔一致。這組計時的終點不同，不能直接比較網路傳輸速率。
- 用 winapp 驗證 Windows 11 檔案總管 Ctrl+Alt+N 可帶入實際選取檔案，背景啟動後再次啟動會顯示同一個程序的視窗，關閉主視窗後可從系統匣雙擊重開。已驗證「傳送到」捷徑建立與檔案參數可轉交給執行中的程式。從傳統右鍵選單點選「傳送到 → NearDrop」的整段操作仍待實機手動驗收。

傳輸測試可執行 `pwsh -File scripts/test.ps1`、`pwsh -File scripts/test.ps1 -Stress` 或 `pwsh -File scripts/test.ps1 -LargeFile`。超過 4 GiB 的模式需要至少約 15 GiB 可用空間，會留下接收與同步測試資料。使用 Microsoft winapp CLI 與互動式桌面時，可執行 `pwsh -File scripts/test-installer.ps1` 測試安裝檔。`test-results` 內含測試專用金鑰，請勿分享整個目錄。

## 兩台實機仍待驗收

1. 準備 Windows 10 x64 與 Windows 11 x64 各一台、一般使用者帳戶、不同 ISP 或其中一台使用手機熱點。先取安裝檔並比對交付的 SHA-256。保留預設安全防護及防火牆，不改系統政策。
2. 兩端只執行單一安裝檔，從開始功能表啟動。記下裝置 ID，退出再開確認不變。先由 A 加 B，確認 B 未自動授權，再由 B 核對並加入 A。記錄連線是否直連或中繼。若網路環境無法連線，記錄出錯、網路類型與防火牆政策。
3. 準備至少 4 GiB 的檔案、數千小檔、空目錄及繁體字檔名。分別用拖曳、選檔、右鍵「傳送到」及前景檔案總管 Ctrl+Alt+N 選取，B 手動接受。用 PowerShell `Get-FileHash -Algorithm SHA256` 對照原檔與保存副本，核對目錄、名稱、數目及空資料夾。
4. 傳輸途中讓 B 離線，再恢復。確認完成與獨立保存是兩個狀態。B 完成保存後，從測試來源刪檔並讓 A 撤銷共享，核對 B 檔案雜湊仍相同。若有額外測試裝置，再測未授權身分與已配對的第三人皆取不到 A 給 B 的分享。
5. 用專用測試目錄建立固定資料夾，B 接受後新增、修改、刪除測試檔，核對等待時間、單向性、暫停與續傳。將大型檔分別作為單次與固定資料夾測試，在相同直連或中繼條件下記錄傳輸、保存時間及磁碟用量。
6. 驗證關閉主視窗後可從系統匣返回，也可退出並停止引擎。勾選登入啟動後真正重啟，確認背景啟動、配對與工作恢復。退出後從 Windows 已安裝的應用程式移除，確認程式捷徑已移除、收件／備份保留，重新安裝後原裝置 ID 仍可用。

目前實機缺口包括兩台不同網路的端到端測試、真正重新開機、乾淨的 Windows 10 與 11、傳統右鍵操作及快捷鍵在其他版本檔案總管的相容性，以及接近 100,000 項上限的小檔壓力測試。
