# 後續工作與更新方式

目前實作包含四階段的基本可用流程，仍屬預覽版；實際已執行項目見 TESTING。

發佈給朋友作日常使用前，優先完成：

1. 兩台真實 Windows 電腦跨不同 ISP／手機熱點、直連與中繼、Windows 10／11 及重開機驗收。已在本機實傳超過 4 GiB 的檔案，仍需接近 100,000 項上限的小檔壓力測試及斷電恢復測試。
2. 簽署安裝器、應用程式及卸載程式，建立獨立可信的 release checksum 發佈通道；加入 CI 與版本化 artifact inventory。現有 SHA 雜湊不能代替發佈者身分簽章。
3. 在現有磁碟剩餘空間門檻與拒絕單次邀請之上，加入每位朋友與每次收件的可配置配額、預期容量預覽、封鎖清單及來源寫入穩定性提示。
4. 加入安全的跨裝置保存回執。現有傳送暫存可在撤銷共享後手動清理，由發送者先向朋友確認是否已保存。
5. 跨磁碟 `.saving` 的逐檔恢復、突然斷電的檔案系統耐久性、損壞日誌的引導恢復、更多當機注入測試。當前同磁碟保存有意圖日誌與唯一目錄恢復，不宣稱任意斷電零損失。
6. QR Code／包含完整 ID 的邀請資訊，仍需雙方核對與明確授權。Windows 11 新式右鍵選單需簽署及封裝 Shell 擴充，目前使用傳統「傳送到」。Ctrl+Alt+N 會保存設定，部分多分頁選取仍需驗收。
7. 活躍工作量上限、可調整頻寬、事件驅動狀態、更完整傳輸失敗原因、紀錄篩選／清理與每工作長期速率圖；目前速度為近期區塊完成速率。

## 更新

更新前從系統匣退出，保留並安全備份 `%LOCALAPPDATA%\NearDrop\Data`，再執行可信的新完整安裝器。不會重建既有裝置身分，也不會下載未驗證內容後執行。安裝檔目前支援重新覆蓋修復，沒有自動回滾的網路更新機制。

升級 Syncthing 時先檢查官方 release 與安全公告，取得官方 archive、更新 `vendor/syncthing.lock.json`、程式中的固定版本及 EXE hash、專案內容路徑及授權來源，保留對應授權與通知，跑全部雙節點整合／實機測試。不要只把下載網址改為 latest。API 可能變動，更新時需檢查 `/rest/config/defaults/*`、狀態 JSON、程序旗標與 Windows 支援條件。

未來更換引擎需實作 `ITransferEngine` 的能力及生命週期，並將應用服務的 Syncthing 設定 JSON 映射抽成更完整的 domain adapter。UI、佇列、收件保存與 Windows 系統整合已有分離，未承諾零修改即可換引擎。
