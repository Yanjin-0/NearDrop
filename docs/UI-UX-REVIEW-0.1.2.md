# NearDrop 0.1.2 UI/UX 評估

2026-11-19。現版適合熟悉流程的人試用。初次安裝的朋友仍需要知道如何配對、何時算送達、哪個按鈕會停止傳輸，以及接收後如何保存。深色基礎、固定導覽、清楚的拖曳區、持續同步刪除提示及清理前的確認值得保留。優先改善操作與狀態，再調整外觀。

以 winapp 在 Windows 11、150% DPI 檢查六個頁面的實際畫面，並用本機隔離測試資料呈現多種工作狀態。實際點測無收件人、誤用接收操作、跨頁訊息及配對欄位自動化名稱。其餘由畫面與程式碼走查。沒有兩台異地電腦、Windows 10、多螢幕、完整螢幕閱讀器測試或真實使用者訪談。

## 等第

| 等第 | 定義 | 本次項數 |
| --- | --- | ---: |
| P0 | 已確認有不可逆資料損失、越權或核心流程全面中斷 | 0 |
| P1 | 對核心任務、資料安全理解或基本可及性有重大影響 | 12 |
| P2 | 降低效率、可理解性或操作一致性 | 16 |
| P3 | 視覺與完成度，適合在核心流程穩定後處理 | 6 |

「實測」為 winapp 可重現的行為。「畫面」為實際視窗呈現。「程式碼」為從目前實作可判讀，尚未逐項用真實傳輸重現。混合證據時以必要的較弱證據標註。

## P1 優先修正

| # | 頁面或流程 | 問題與建議 | 證據 |
| --- | --- | --- | --- |
| 1 | 送出前條件 | 沒有檔案或朋友時，「傳送」仍可按，錯誤遠離按鈕。依引擎、檔案、收件人三個條件啟用按鈕，在旁邊提示缺少哪一步，並提供「新增朋友」。已選取檔案時要保留選取。 | 實測 |
| 2 | 收件操作 | 待接受、接收中、待保存、已保存共用四個按鈕。選取已保存項目仍能按「接受」，之後才出錯。依狀態顯示可用動作，讓「接受邀請」和「保存到收件位置」只出現在對應項目。 | 實測 |
| 3 | 送達與保存 | 發送端介面已有「保存狀態未知」，但完成、取消和清理的主流程缺少一致的階段導覽。以「等對方接受 → 傳輸中 → 對方已接收／保存狀態未知」呈現，接收端明確顯示「待保存 → 已保存」。只有驗證過的回執才可以改成「對方已保存」。 | 畫面及程式碼 |
| 4 | 停止共享 | 「取消共享」「停止共享」直接執行，容易讓尚未接收或保存的人失去這次共享。進行中的工作先顯示檔名、對方和影響，再用「停止這次傳送」確認。持續同步應另用「停止持續同步」。 | 程式碼 |
| 5 | 大檔準備與保存 | 建立暫存、保存與清理皆停用整個視窗。長任務只有底部一行文字，沒有準備進度；大檔準備也沒有 UI 取消入口。改成工作列上的進度、可安全取消點和錯誤恢復，並保留切換頁面與查看其他工作。引擎真的暫停時要明示。 | 程式碼 |
| 6 | 傳送清單 | 再選一次或從總管帶入會整批取代。畫面只顯示前四個名稱，無法展開、移除或核對全部項目。做成可檢查、追加、移除與清空的清單，顯示總數、容量與暫存空間預估。全數無效的外部路徑也應清除舊提示。 | 程式碼 |
| 7 | 新手配對 | 「我的裝置」是每次啟動預設頁。第一次使用時，表單讓人自己推斷如何交換 ID；傳送空白頁有文字提示但沒有直達按鈕。用簡短的「複製我的 ID → 貼上對方 ID → 雙方確認」流程。已有朋友時回到最近頁或傳送頁。 | 畫面及程式碼 |
| 8 | 錯誤與恢復 | 同一條底部提示跨頁保留；換頁後仍看到「請先選取收件朋友」。錯誤常直接顯示例外文字，啟動失敗缺少重試入口。每頁顯示與當下操作相關的錯誤及可執行的下一步；全域區只顯示引擎、連線等全域狀態。 | 實測及程式碼 |
| 9 | 邀請通知 | 接收頁籤沒有待處理數量，現有系統匣通知主要在接收或保存完成後觸發。App 躲到系統匣時，新邀請可能沒被看見。新增「待接受／待保存」計數、邀請通知，以及點擊後跳到該工作。 | 程式碼 |
| 10 | 配對可及性 | 「朋友名稱」「朋友的完整裝置 ID」視覺上有標籤，但實測兩個輸入欄位的 UIA `Name` 都是空值。使用關聯標籤及錯誤提示，檢查 Tab 順序、焦點返回和讀屏宣讀；主要清單及拖曳區也應有可讀名稱。 | 實測 |
| 11 | 高 DPI 與小視窗 | 目前最小高度固定 620 DIP。在 150% DPI 相當於 930 實體像素，超過常見 768 像素螢幕的可用高度。預設 150% 的設定頁已需捲動才能看到退出。降低最小尺寸，讓左欄可收合、底部主要操作留在畫面內。 | 畫面及程式碼尺寸換算 |
| 12 | 狀態與實際檔案 | 已保存列仍能顯示 100% 和 0 KB/s；搬走保存檔後，開啟位置可能無反應。持續同步總量為 0 時也無法進入現有的「目前已同步」判定。區分「目前無檔案」「已同步」「已保存」「檔案已移動」，按鈕應有明確結果。 | 畫面及程式碼 |

## P2 改善效率與一致性

| # | 頁面或流程 | 問題與建議 | 證據 |
| --- | --- | --- | --- |
| 13 | 傳輸紀錄 | 沒有「進行中／待處理／完成／失敗」篩選，也沒有檔名、朋友、日期搜尋。長期使用後很難找到指定工作。加入篩選、搜尋、時間與方向，預設優先顯示待處理。 | 畫面 |
| 14 | 工作列排版 | 檔名、朋友、狀態、速度、百分比、完整路徑擠在同一文字區。長檔名與路徑占多行。用分欄和狀態標籤，長文字截短、完整值放詳細資料並可複製。 | 畫面 |
| 15 | 進度視覺化 | 只有文字百分比與容量。活躍工作加入進度條及已傳／總量，速度或預估時間可可靠計算時再顯示。離線、暫停、已完成應突出原因並隱藏無效速度。 | 畫面 |
| 16 | 工作操作層級 | 「重試／恢復」「取消共享」「開啟傳送暫存」「清理傳送暫存」都用相同按鈕樣式，部分動作對某種工作完全無效。只保留當前工作最需要的主按鈕，其他動作放在選單，永久清理用明確危險樣式。 | 畫面及程式碼 |
| 17 | 清理確認 | 已有安全的預設否與永久刪除說明，但對話框沒指出是哪筆工作、對方是誰、實際會釋放多少空間。顯示工作名與收件人，能取得時顯示暫存大小、進行中的其他傳輸，以及清理中斷後可重試。 | 程式碼 |
| 18 | 刷新穩定性 | 定時整批替換清單，雖然嘗試恢復選取，但未明確保留捲動位置、鍵盤焦點，瞬間更新也容易打斷操作。保留項目身分，個別更新狀態與進度。 | 程式碼 |
| 19 | 寄件人／朋友狀態 | 離線與等待對方確認合成一種狀態，已連線時仍可能要等共享邀請。持續區分「已加入」「離線」「可連線」「等待接受」，不推測對方裝置狀態。 | 程式碼 |
| 20 | 傳送成功後導覽 | 建立工作後直接切換到傳輸紀錄，但沒有定位或醒目標示剛新增的工作。以本頁回饋配合「查看進度」，需要跳頁時聚焦該工作。 | 程式碼 |
| 21 | 收件邀請資訊 | 接受前可讀到名稱與方向，沒有可信大小、預期儲存位置或空間資訊。至少標明目的地、持續或單次；大小未知時明說，顯示可用空間及保留門檻。不要把對方可自行填寫的數字當作保證。 | 程式碼 |
| 22 | 收件資料夾入口 | 「開啟收件位置」依選取項目切換目標。對尚未保存的工作可能開到暫存，沒選到工作時開預設下載位置。把「開啟已保存檔案所在資料夾」與固定的「開啟收件資料夾」分開。 | 程式碼 |
| 23 | 持續同步 | 自動傳送頁混合我傳出的監控資料夾與朋友傳來的鏡像，行內看不出方向和路徑。以「我分享的」「朋友分享給我」分組，顯示來源或所在位置、對象與當前動作。 | 畫面及程式碼 |
| 24 | 新增持續同步 | 先開選朋友對話框，再開資料夾對話框，最後確認。沒有朋友也先開一個無法完成的選擇視窗。改成可返回的同頁表單或簡短嚮導，先顯示收件人、來源和刪除影響。 | 程式碼 |
| 25 | 設定資訊架構 | 收件路徑、背景、總管整合、隱私、版本、退出都排在長頁。「加入右鍵傳送到」沒有已安裝狀態或移除入口；快捷鍵衝突仍可能保持勾選。依用途分組，分開顯示偏好與目前是否生效。 | 畫面及程式碼 |
| 26 | 通知和系統匣 | 重啟可能再次提示舊的已保存工作，關窗也會反覆提示背景執行。只對新狀態通知，提供通知偏好，系統匣顯示可理解的傳輸與待處理狀態。 | 程式碼 |
| 27 | 用語和狀態 | 頁籤「接收」、內頁「收到的檔案」同時含邀請；「自動傳送／固定資料夾／持續同步」並用；偶爾露出 `tcp-client`。建立一致詞彙。直連、中繼與錯誤原因使用一般使用者能讀懂的詞。 | 畫面及程式碼 |
| 28 | 退出與重啟 | 退出是設定頁最下方，亦可從系統匣進入。大工作未完成時，缺少退出影響與正在關閉的狀態。把退出設在容易找到的應用程式選單，若有工作再說明是否能續傳。 | 畫面及程式碼 |

## P3 視覺與完成度

| # | 頁面或流程 | 問題與建議 | 證據 |
| --- | --- | --- | --- |
| 29 | 版面密度 | 頂部品牌與標語占用較多垂直空間，空清單也保留大面積。縮短品牌區，空白頁以一則具體提示和下一步取代重複區塊。 | 畫面 |
| 30 | 色彩、狀態與焦點 | 深色底與不同綠色色塊方向一致，但主按鈕、次要、危險、提醒狀態區別不足。指定少量清楚的角色色，搭配圖示和文字。選取、滑過、鍵盤焦點需各自看得見，另以 Windows 高對比模式測試。 | 畫面 |
| 31 | Windows 外觀 | 白色標題列、亮捲軸、預設程式圖示與深色內容不一致。先修整圖示及原生樣式，保留 Windows 的縮放和視窗貼齊行為。 | 畫面 |
| 32 | 字級及數字 | 清單中的檔名、狀態、大小、進度權重接近。用主標／次標、行距和數字對齊提高掃讀性；容量單位和小於 1 KB 的格式統一。 | 畫面 |
| 33 | 拖曳回饋 | 可放置區已有邊界，但拖曳中只設定游標效果。可加可放置區高亮、加入後的小回饋，以及不支援項目的行內提示。 | 畫面及程式碼 |
| 34 | 說明及版本 | 設定頁隱私文字很長，開啟說明只能先進資料夾。設定顯示簡短摘要，提供直達安全說明、複製版本和開啟儲存位置。 | 畫面及程式碼 |

## 建議施工順序

1. 第一批做 P1 #1–#4、#8、#10。以現有 UI 就能改善操作有效性、錯誤位置、狀態文案及欄位名稱。
2. 第二批重做傳送選取與收件佇列，再加上大檔進度、邀請通知、初次配對及小視窗支援。
3. 第三批整理紀錄、設定、通知與狀態視覺。以 Windows 10 和 Windows 11、100%／150%／200% DPI、鍵盤操作、長檔名與多筆紀錄回歸驗收。

最基本的驗收是讓首次安裝的朋友從空白畫面完成配對與第一次收件，能清楚回答「目前誰需要做什麼」「檔案是否已保存」「按這個按鈕會停止什麼」。
